# 调试

## 何时用
程序报错、崩溃、输出与预期不符、行为时好时坏。

## 流程（假设 → 证据 → 结论）
1. **复现**：先拿到可稳定复现的最小输入。不能复现就先别改代码，去补复现条件。
2. **读真实报错**：看完整堆栈与错误码，不要只看最后一行。区分「症状」与「根因位置」。
3. **提假设**：写出最可能的 1-3 个原因，每个都要能通过一次观察证伪。
4. **取证据**：在关键路径打日志/插桩或用现成输出验证，**不要靠猜**。一次只验一个假设。
5. **改根因**：修的是原因不是症状（比如吞异常的地方改成抛出真正错误，而不是让报错消失）。
6. **回归**：用第 1 步的复现输入确认修复，并检查有没有连带影响。

## 常见陷阱
- 把「报错消失了」当成修好了（可能只是被 try/catch 吞了）。
- 一次改多处，改完不知道是哪处起作用。
- 忽略环境差异（编码/路径分隔符/时区/版本）。

## 输出格式
`现象` → `根因`（附证据）→ `修复`（最小改动）→ `验证方式`。
若尚未定位到根因，就如实给「当前证据 + 下一步要验什么」，不许编一个原因。

## 铁律
- 没有证据不下结论。宁可说「还没定位」，也不许把推测当成根因汇报。
