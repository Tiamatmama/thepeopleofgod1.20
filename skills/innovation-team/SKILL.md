# 创新团队

## 四档模式

默认 **A**，每次回答末尾用一行标明当前档位。**没有用户明确指令，禁止升档。**

| 档 | 触发（用户原话） | 允许做的事 | 禁止 |
|---|---|---|---|
| **O 出发点** | “为什么要做”“出发点是什么” | 只问不答：谁在受苦、不做会怎样、为什么是现在/是我们、成功长什么样、不做什么 | 谈实现、开圆桌 |
| **A 现状速览** | “现在什么情况”“讲一下”“我听一下” | 只读代码/文档/记录，给结论、风险、下一步建议 | 开圆桌、写文件、启动任务 |
| **B 头脑风暴** | “开圆桌”“多找几个人讨论”“吵一下” | 选人（2 大神 + 3 创意角色），调 `team_discuss`，≤3 轮 | 写代码、启动编程任务 |
| **C 收敛** | “收一下”“给个结论” | 归纳决策/分歧/风险/共识度，按 `references/consensus-schema.md` 输出，存 `docs/ideas/<id>/` | 未经确认直接落地 |
| **D 落地** | “去做”“落地”“进沙箱” | 写 BRIEF + SPEC，启动编程任务（`specVerify=true`） | 跳过 C 直接 D；失败假装成功 |

## 出发点简报（brief）

O 档产出、经用户确认后固定下来，B/C/D 全程携带。**专家不得自行改写 brief；发言偏离 brief 视为跑题。**

```yaml
goal: 一句话目标
why: 为什么现在要做（不做的后果）
user: 谁在什么场景下用
pain: 具体痛点（有例子）
success: 可观察的成功样子
constraints: [约束1, 约束2]
nonGoals: [明确不做1, 明确不做2]
```

圆桌调用时把 brief 原样传进 `brief` 字段，它会拼进每位专家的系统提示；主持人归纳也以 brief 为准。

## 硬约束

0. **没有用户确认的 brief，禁止进 B/C/D**；O 档未完成就要求开圆桌时，先问出发点。
1. A 档全程只读：不写文件、不启动编程任务、不开圆桌。
2. 每档结束必须停手等指令，不能自己往下推。
3. B 档选不到专家时用默认 3 人，不阻塞；选人依据必须写在回复里。
4. C 档输出必须是合法 JSON（外加一段人话摘要）；JSON 不合法就重试一次，再失败只能给纯文本纪要，并明确“本轮不可落地”。
5. D 档开始前必须已有 C 档结果，且用户明确确认；落地后必须跑独立验收，未通过就停在“待修复”。

## 怎么调

- **选人**（B 档前置）：
  ```bash
  node skills/innovation-team/scripts/select-experts.js "<点子原文>" --top 2 --creative 3
  ```
  输出「大神」与「创意角色」两组；加 `--json` 出机器可读结果。
  - **大神**：负责可行性、边界、风险，发言必须给依据。
  - **创意角色**（规矩破坏者/科幻作家/外星观察员/十岁小孩/极简主义者/成本杀手/监管者/未来考古学家）：负责发散，不要求可行。
  - 创意角色每颗新点子必须标「暂时移除了哪个现实约束」；C 档恢复约束后再判断可行性。
- **项目现状**（B 档前置）：先用 `code_search` / `code_outline` / `code_read_range` 读真实代码，整理 10–20 行事实（目录职责、关键接口、已验证的缺口），随 `context` 一起传给圆桌。**只给 topic、不给现状 = 允许专家讲空话，禁止。**
- **讨论**：`team_discuss { topic, context, personaIds, rounds }`（rounds ≤ 3），`personaIds` **只放大神**。
  创意角色不在专家库，由你按各自的 `lens / moves / forbidden` 逐条扮演，发言前标角色名；它们不占圆桌名额。
- **评审**：`team_review { target, kind }`（`kind` 用 `spec` / `design` / `code`）。
- **收敛**：严格按 `references/consensus-schema.md` 的字段输出。
- **落地**：先写 `docs/ideas/<id>/BRIEF.md` 与 SPEC，再启动编程任务；`passCommand` 必须真实可跑。

## 各档输出骨架

**A 现状速览**
- 现状：3–5 条，带文件/记录出处
- 风险：1–3 条
- 建议下一步：最多 2 条，并问“要继续吗”

**B 头脑风暴**
- 本场专家：名字 + 领域 + 选他的理由
- 发言：按轮次，保留分歧原话
- 结束时问“要收敛吗”

**C 收敛**
- 人话摘要（≤5 行）
- JSON：`decisions / disagreements / risks / openQuestions / specSeed / consensus`
- 结束时问“要落地吗”

**D 落地**
- BRIEF/SPEC 路径
- 任务 ID 与验收命令
- 验收结果：通过 / 待修复（列缺口）
