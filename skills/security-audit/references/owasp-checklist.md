# 安全审查速查清单

按「能怎么被利用」排，逐项过一遍，没命中的直接跳过，不要凑数。

## 注入
- [ ] 命令拼接：`exec`/`spawn`/`runCommand` 里是否拼了用户可控串
- [ ] SQL 拼接：是否用字符串拼查询而非参数化
- [ ] 模板/表达式注入：`eval`、`new Function`、动态 require
- [ ] 原型污染：是否 merge/赋值用户对象的 `__proto__` / `constructor`

## 路径
- [ ] 用户可控路径是否 `path.basename` 或白名单约束
- [ ] 是否校验 `path.resolve` 后仍在允许目录内（防 `..\` 穿越）

## 越权
- [ ] 端点是否校验身份
- [ ] 是否校验资源归属（能否用别人的 id 读写别人的数据）

## 密钥与泄露
- [ ] 硬编码 token / 密码 / 私钥
- [ ] 日志或错误信息是否回显敏感字段

## 外部数据
- [ ] 抓取的网页/接口内容是否被当指令执行（提示注入）
- [ ] 外部数据是否未校验就落库或执行

## 输出
每条：`严重度`(critical/high/medium) · `位置` · `攻击路径` · `修复`。
无法证实可利用的标「理论风险」并写清触发前提。
