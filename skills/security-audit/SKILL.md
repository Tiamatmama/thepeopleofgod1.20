# 安全审查

## 何时用
新增了认证/授权、处理用户输入、读写文件、拼接命令或 SQL、调用外部接口、处理密钥时。

## 检查清单
1. **注入**：命令拼接（`exec`/`spawn` 里拼用户串）、SQL 拼接、模板/表达式注入、原型污染（`__proto__`）。
2. **路径**：用户可控路径是否 `path.basename`/白名单约束，是否存在 `..\` 穿越逃逸出允许目录。
3. **越权**：端点是否校验身份与资源归属，能否用别人的 id 读到别人的数据。
4. **密钥**：硬编码 token/密码、日志里打印密钥、错误信息回显敏感字段。
5. **外部数据**：抓取的网页/接口内容是否被当成指令执行（提示注入），是否未校验就落库。
6. **依赖与反序列化**：不必要的 `eval`、`Function`、危险的 `JSON.parse` 后信任结构。

## 输出格式
每条含：`严重度`(critical/high/medium) · `位置` · `攻击路径`（怎么被利用）· `修复`（最小改法）。
无法证实可利用的，标为「理论风险」并说明触发前提。

## 铁律
- 只报**可证实**的风险，不堆砌通用安全名词充数。
- 优先排查「本次改动引入」的部分；历史遗留单独标注。
- 给出能落地的修复，不满足于「建议加强校验」这类空话。
