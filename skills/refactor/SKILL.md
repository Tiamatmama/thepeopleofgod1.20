# 重构

## 何时用
代码能跑但难读、难改、重复、职责混杂，需要整理结构时。

## 原则
1. **行为不变**：重构只改结构不改外部可见行为。改行为要单独拎出来说。
2. **小步走**：每次只做一种手法（提炼函数、内联、改名、拆类、去重），每步都能独立验证。
3. **先立护栏**：动手前确认有无测试；没有就先用最小脚本或调用验证关键路径，作为回归基线。
4. **不许顺手加功能**：发现的问题记录到「另议」，不夹带进重构。

## 常见手法
- 长函数 → 按「做什么」切分，命名用意图而非实现。
- 重复三处以上 → 提炼，但两处重复且正交时不必强行合并。
- 深层条件嵌套 → 卫语句提前返回。
- 布尔参数 / 标志位 → 拆成两个明确命名的函数。

## 输出格式
`目标` → `步骤清单`（每步：改哪里、用哪手法、如何验证）→ `风险与另议`。
每步都要能单独回退。

## 铁律
- 不为了「看起来优雅」引入新抽象层。三行重复好过一个用一次的抽象。
- 不改没有证据支持的「性能优化」；那属于性能技能。
