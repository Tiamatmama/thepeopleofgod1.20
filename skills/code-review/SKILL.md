# 代码评审

## 何时用
需要判断代码质量、找出缺陷与隐患、给出可执行的修改建议时。评审对象可以是整文件，也可以是 diff。

## 评审维度（按此顺序，逐项给结论）
1. **正确性**：边界条件（空值/0/负数/超长/并发）、错误处理是否吞异常、循环与终止条件、整数/浮点精度。
2. **安全**：见 `security-audit` 技能，此处只扫明显的注入、越权、路径穿越、硬编码密钥。
3. **可维护性**：命名、函数长度与单一职责、重复代码、隐式耦合、魔法数字。
4. **资源**：文件/连接/进程是否释放、是否有未清理的定时器与监听器。
5. **一致性**：是否与所在代码库既有风格与抽象层次一致。

## 输出格式
先给一句话结论（能不能用），再给问题清单，每条含：
- `严重度`：blocker / major / minor / nit
- `位置`：文件:行 或 函数名
- `问题`：一句话说清
- `建议`：具体怎么改（给最小改法，不要重写整段）

## 铁律
- 只报你**在代码里看得到的**问题，不臆测运行时状态。看不到的地方标「需确认」。
- 不要为了凑数列 nit。没有 blocker 就明说没有。
- 不擅自改需求：你评审的是实现，不是替产品做决定。
