# 测试编写

## 何时用
新增或修改了函数、接口、数据处理逻辑，需要证明它在各种输入下都正确时。

## 原则
1. **测行为，不测实现**：断言「输入→输出/副作用」，不要断言内部私有方法的调用次数。
2. **先想怎么弄坏它**：列边界与异常，再列正常路径。空值、0、负数、超长、单元素、重复、并发。
3. **一个用例一个断言点**：失败时能立刻看出是哪条规则破了。
4. **可复现**：每个用例自带固定输入，不依赖时间、随机数、网络、执行顺序。
5. **慢/外部依赖**要 mock 或隔离；不确定性来源必须被钉死。

## 用例矩阵（照这个表铺开）
对每个输入维度取：正常 / 边界 / 越界 三档，组合出必测项：
- 正常输入 → 期望正常输出
- 空 / null / undefined
- 边界值（0、1、最大、刚好等于阈值、刚好超阈值）
- 错误输入（类型错、格式错）→ 期望明确的失败，而非崩溃或静默

## 输出格式
`被测对象` → `用例清单`（每条：输入 → 期望 → 类型[正常/边界/异常]）→ `建议的测试文件位置`。
如发现当前代码有未覆盖的关键分支，单独列出。

## 铁律
- 不写「调用一下不报错就算过」的空测试。没有断言的测试等于没测。
- 测到 bug 时，先把它变成一条会失败的用例，再谈修。
